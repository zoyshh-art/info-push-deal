# 好价监控（vivo 手机 + AI 免费额度）

从 [info-push](https://github.com/zoyshh-art/info-push) 拆分出来的独立盯价仓库。

仓库里跑两个互不干扰的监控，各有独立的脚本和工作流：

| 监控 | 脚本 | 频率 | 推送内容 |
|---|---|---|---|
| 手机好价 | `scripts/phone_deal.py` | 2 分钟一轮 | vivo 机型低于发行价 35% |
| AI 免费额度 | `scripts/ai_deal.py` | 每小时 | 新增免费 LLM 服务商/模型、额度变化、模型降价 |

> **2026-11-04 更新**：按用户要求下线 **打印机**（兄弟 T435W / 爱普生 L335x）与 **OPPO 手机**（Find X9 / X10 系列）。
> 代码与配置全部保留，靠脚本顶部两个开关控制，改回 `True` 即恢复，无需回滚：
> ```python
> PRINTER_ENABLED = False   # 打印机到手价区间监控
> OPPO_ENABLED = False      # OPPO 型号匹配 + 官方商城盯价 + 搜索关键词
> ```

**为什么单独开一个公开仓库**：GitHub Free 的私有仓库只有 2000 分钟/月 Actions 额度，按 job 向上取整计费。
好价监控单次约 1 分钟，要高频盯价就必须单独放在**公开仓库**——公开仓库的 Actions 分钟数不计费，
可以做到 **2 分钟一轮**，比原来私有仓库里的 30 分钟一轮快 15 倍。

## 监控范围

| 来源 | 抓什么 | 状态 |
|---|---|---|
| 什么值得买（榜单 / 分类 API / 关键词搜索 / 首页） | 手机好价爆料 | 启用 |
| ZOL 中关村在线 | 手机降价行情 | 启用 |
| IT之家 | 手机促销资讯 | 启用 |
| 快科技 | 促销资讯 | 启用 |
| 什么值得买关键词搜索（DCP-T435W / L3351 / L3353） | 打印机好价爆料 | **已停跟** |
| OPPO 官方商城 | 7 款目标机型直降 | **已停跟** |

型号白名单：vivo X300 系列（X300 Pro / X300 Ultra）、X500 系列（前缀匹配，含未来后缀）。
已停跟：Find X9 基础款、vivo X300 / X300s / X300E（`EXCLUDED_MODELS`）；OPPO Find X9/X10 全系（`OPPO_ENABLED = False`）。

打印机盯两款（`PRINTER_TARGETS`，`PRINTER_ENABLED = False` 时不抓不判）：

| 型号 | 到手价区间 | 匹配规则 |
|---|---|---|
| 兄弟 DCP-T435W | ¥400–500 | `T435W(?!\d)`，精确排除 T436W |
| 爱普生 L335x | ¥400–600 | `L\s?335\d(?!\d)`，覆盖 L3350–3359 全系 |

标题命中耗材词（墨水 / 墨盒 / 维护箱 / 相纸 / 兼容 / 格之格 等，`PRINTER_ACC_RE`）一律丢弃，避免「适用 L3351 的第三方墨水」被当成打印机。

## 推送规则

手机和打印机是**两套判定口径**，互不影响：

- **手机**：低于发行价 35% 才推，达不到的静默淘汰，不打扰
- **打印机**：到手价**落入上表区间**才推（不看发行价折扣），高于上限或低于下限都不推
- **按机型级去重**：`Find X9 Pro` / `X9s Pro` / `X9 Ultra` 各算各的，同价不会被合并
- 手机价格按 **10 元** 归档（3441.65 / 3441.7 / 3442 算同一档），打印机按 **5 元** 向下取整
- **同一「机型 + 价格档」24 小时内只推一次**；隔 24 小时再出现，可以再提醒一次
- 同机型 **24 小时内价格相差 ≤1%** 也视为同一条信息，避免不同渠道差几块钱就被当成新降价
- 价格真降了会落到新档位，立刻作为新条目推送，不受 24 小时限制
- 资讯按链接永久去重（新闻没有"降价"概念），不设时间窗口
- 单条消息 ≤10 条，单轮 ≤4 条消息，超出部分下一轮巡检续推
- 正文按「🖨️ 打印机好价 / 📱 手机好价」分段，标题随内容变（只有打印机时标题写打印机好价）
- 首次运行只记基线不推送（避免一上线就刷屏）

节流状态存在 `data/phone_deal_state.json`，由工作流自动提交回仓库。

## 部署

在仓库 `Settings → Secrets and variables → Actions` 添加：

| Secret | 说明 |
|---|---|
| `PUSHPLUS_TOKEN` | PushPlus 令牌，微信接收推送 |

推送渠道默认 `clawbot`（微信 ClawBot）。如需服务号渠道，在工作流里加环境变量
`PUSHPLUS_CHANNELS: "wechat,clawbot"`。

## 巡逻节奏

**全天 24 小时不间断，每 2 分钟扫一轮。**

实现方式是「每小时触发一次 job，job 内部自己循环 25 轮、每轮间隔 2 分钟」，而不是直接写
`cron: "*/5 * * * *"`。原因是实测发现 GitHub 对高频 cron 会降级调度——配置写 5 分钟，
实际只跑了 30 分钟一次、中间 20 分钟完全空转；而每小时一次的频率 GitHub 调度是可靠的。
把 2 分钟粒度放进 job 内部，就不受平台定时精度影响了。

上一轮还没跑完时下一次触发会在队列里等待，等它结束立刻接上，所以实际是连续覆盖、没有空档。

工作流也可以手动触发：**Actions → 手机好价监控 → Run workflow**，
勾选 `dry_run` 只打印不推送，`loops` 填轮数（默认 12 轮 = 60 分钟，调试填 1 就行）。

> 高频轮询下绝大多数轮次没有任何状态变化。脚本会在落盘前比对内容，**没有实际变化就不写文件**，
> 工作流看到 `no state changes` 会直接跳过 commit——否则一天几百轮会刷出几百个空 commit。
> 每轮结束都会把状态提交掉，万一长 job 中途被取消，已推送的记录也不会丢、不会重复推。

## 本地运行

```bash
pip install -r requirements.txt
export PUSHPLUS_TOKEN=你的令牌      # Windows: set PUSHPLUS_TOKEN=...
python scripts/phone_deal.py --dry-run   # 手机好价，只打印
python scripts/phone_deal.py             # 手机好价，真实推送
python scripts/ai_deal.py --dry-run      # AI 免费额度，只打印
python scripts/ai_deal.py                # AI 免费额度，真实推送
```

# AI 免费额度监控（`scripts/ai_deal.py`）

盯「哪里能白嫖」和「哪家活动变了」，**不推模型降价、不发教程水文**。每小时巡检一次。

## 三个源，按信号价值排序

| 源 | 拿到什么 | 为什么选它 |
|---|---|---|
| ★ `rockbenben/free-llm-intel` | **每天 70 家厂商的免费额度政策变化**，带前值→后值的中文摘要 | 它已经替你把 OpenAI / Anthropic / Gemini / Groq / DeepSeek / 通义 / Kimi / 智谱 / 豆包 等官方页面巡检了一遍，还做了英文精译。是唯一能持续产出「最新免费 token / 活动」的源 |
| `mnfst/awesome-free-llm-apis` | 15 家服务商的永久免费层、全部模型、限流额度 | 12k+ star，`data.json` 是结构化数据，比解析 README 可靠 |
| OpenRouter `/api/v1/models` | 453 个模型的实时价格 | 只取「完全免费」（输入输出单价都为 0）的模型增减 |

第一个源是关键。之前只用后两个时，只能看到「长期不变的免费清单」和「价格波动」，抓不到「哪家刚放活动」——而这恰恰是最有价值的部分。

## 监控什么

| 事件 | 判定方式 |
|---|---|
| **免费政策变化** | intel changelog 里出现未推送过的「厂商 + 日期」记录 |
| 新增免费服务商 | `data.json` 里出现未记录过的 provider |
| 免费清单新增模型 | 已存在的 provider 下出现新 model id |
| 免费额度变化 | provider 的 `description` / `baseUrl` 内容哈希变了 |
| OpenRouter 新增免费模型 | 输入与输出单价都为 0，且未记录过 |

intel 源按「厂商 + 日期」去重，同一天同一家最多推一条——changelog 一天内可能多次修订，按内容哈希去重会刷屏。

## 试过但放弃的源

- **模型降价**：用户明确说没价值。而且 OpenRouter 是聚合器，价格随上游路由分钟级抖动（实测 `gpt-oss-120b` 在 `$0.113` 和 `$0.75` 之间来回跳），噪音远大于信号
- **Hacker News 关键词搜索**：搜 `free API credits` 返回的全是无关 Show HN，加分和时效过滤后依然如此
- **官方博客 RSS**：OpenAI 的 RSS 有 1355 条，全是收购 / 任命 / 安全公告，跟免费额度无关，信号密度极低
- **Reddit**：本地网络被代理拦截，无法验证；且需要额外的反爬处理
- **LiteLLM 价格库**：文件超 1MB，GitHub contents API 取不到正文

## 刻意不碰的东西

**国内「API 中转站」「号池」不做监控，也不推荐。**

这类按转售价兜售官方额度的生意，2026 年已被多地警方以非法获取计算机信息系统数据立案，公开报道中有站长被刑事拘留的案例；此外账号随时封禁、请求与数据经第三方转发。本脚本只监控**厂商官方**的免费层与公开定价，清单里出现的中国大陆厂商（Z AI / ModelScope / SiliconFlow）也都是官方渠道。

## 去重规则

- 同一条变化**只推一次**，推过就不再推
- 首次接入 intel 源时只记基线，不会把历史 150 条一次性倒出来（`meta|intel_baselined` 标记）
- 基线存 `data/ai_deal_state.json`，`schema: 2`，保留最近 3000 条

## 频率

`cron: "20 * * * *"`，每小时一次，错开整点（整点是 GitHub 调度高峰）。

intel 源每天更新 1–2 次，每小时巡检足够覆盖。工作流 `ai-watch.yml` 与手机好价的 `deal-watch.yml` 完全独立，互不阻塞。

手动调试：**Actions → AI 免费额度监控 → Run workflow**，勾选 `dry_run` 只打印不推送。
