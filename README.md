# 好价监控（手机 + 打印机）

从 [info-push](https://github.com/zoyshh-art/info-push) 拆分出来的独立盯价仓库。

**为什么单独开一个公开仓库**：GitHub Free 的私有仓库只有 2000 分钟/月 Actions 额度，按 job 向上取整计费。
好价监控单次约 1 分钟，要高频盯价就必须单独放在**公开仓库**——公开仓库的 Actions 分钟数不计费，
可以做到 **2 分钟一轮**，比原来私有仓库里的 30 分钟一轮快 15 倍。

## 监控范围

| 来源 | 抓什么 |
|---|---|
| 什么值得买（榜单 / 分类 API / 关键词搜索 / 首页） | 手机好价爆料 |
| 什么值得买关键词搜索（DCP-T435W / L3351 / L3353） | 打印机好价爆料 |
| ZOL 中关村在线 | 手机降价行情 |
| IT之家 | 手机促销资讯 |
| 快科技 | 促销资讯 |
| OPPO 官方商城 | 7 款目标机型直降 |

型号白名单：OPPO Find X9 系列（X9 Pro / X9s Pro / X9 Ultra）、Find X10 系列、vivo X300 系列（X300 Pro / X300 Ultra）、X500 系列（前缀匹配，含未来后缀）。
已停跟：Find X9 基础款、vivo X300 / X300s / X300E（`EXCLUDED_MODELS`）。

打印机盯两款（`PRINTER_TARGETS`）：

| 型号 | 到手价区间 | 匹配规则 |
|---|---|---|
| 兄弟 DCP-T435W | ¥400–500 | `T435W(?!\d)`，精确排除 T436W |
| 爱普生 L335x | ¥400–600 | `L\s?335\d(?!\d)`，覆盖 L3350–L3359 全系 |

标题命中耗材词（墨水 / 墨盒 / 维护箱 / 相纸 / 兼容 / 格之格 等，`PRINTER_ACC_RE`）一律丢弃，避免「适用 L3351 的第三方墨水」被当成打印机。

## 推送规则

手机和打印机是**两套判定口径**，互不影响：

- **手机**：低于发行价 35% 才推，达不到的静默淘汰，不打扰
- **打印机**：到手价**落入上表区间**才推（不看发行价折扣），高于上限或低于下限都不推
- **按机型级去重**：`Find X9 Pro` / `X9s Pro` / `X9 Ultra` 各算各的，同价不会被合并
- 手机价格按 **10 元** 归档（3441.65 / 3441.7 / 3442 算同一档），打印机按 **5 元** 向下取整
- **同一「机型 + 价格档」24 小时内只推一次**；隔 24 小时再出现，可以再提醒一次
- 同机型 **24 小时内价格相差 ≤1%** 也视为同一条信息，避免不同渠道差几块钱就被当成新降价
- 价格真降了会落到新档位，立刻作为新条目推送，不受 24 小时限制
- 资讯按链接永久去重（新闻没有"降价"概念），不设时间窗口
- 单条消息 ≤10 条，单轮 ≤4 条消息，超出部分下一轮巡检续推
- 正文按「🖨️ 打印机好价 / 📱 手机好价」分段，标题随内容变（只有打印机时标题写打印机好价）
- 首次运行只记基线不推送（避免一上线就刷屏）

节流状态存在 `data/phone_deal_state.json`，由工作流自动提交回仓库。

## 部署

在仓库 `Settings → Secrets and variables → Actions` 添加：

| Secret | 说明 |
|---|---|
| `PUSHPLUS_TOKEN` | PushPlus 令牌，微信接收推送 |

推送渠道默认 `clawbot`（微信 ClawBot）。如需服务号渠道，在工作流里加环境变量
`PUSHPLUS_CHANNELS: "wechat,clawbot"`。

## 巡逻节奏

**全天 24 小时不间断，每 2 分钟扫一轮。**

实现方式是「每小时触发一次 job，job 内部自己循环 25 轮、每轮间隔 2 分钟」，而不是直接写
`cron: "*/5 * * * *"`。原因是实测发现 GitHub 对高频 cron 会降级调度——配置写 5 分钟，
实际只跑了 30 分钟一次、中间 20 分钟完全空转；而每小时一次的频率 GitHub 调度是可靠的。
把 2 分钟粒度放进 job 内部，就不受平台定时精度影响了。

上一轮还没跑完时下一次触发会在队列里等待，等它结束立刻接上，所以实际是连续覆盖、没有空档。

工作流也可以手动触发：**Actions → 手机好价监控 → Run workflow**，
勾选 `dry_run` 只打印不推送，`loops` 填轮数（默认 12 轮 = 60 分钟，调试填 1 就行）。

> 高频轮询下绝大多数轮次没有任何状态变化。脚本会在落盘前比对内容，**没有实际变化就不写文件**，
> 工作流看到 `no state changes` 会直接跳过 commit——否则一天几百轮会刷出几百个空 commit。
> 每轮结束都会把状态提交掉，万一长 job 中途被取消，已推送的记录也不会丢、不会重复推。

## 本地运行

```bash
pip install -r requirements.txt
export PUSHPLUS_TOKEN=你的令牌      # Windows: set PUSHPLUS_TOKEN=...
python scripts/phone_deal.py --dry-run   # 只打印
python scripts/phone_deal.py             # 真实推送
```
